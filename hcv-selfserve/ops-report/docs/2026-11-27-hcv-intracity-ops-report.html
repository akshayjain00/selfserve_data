Definitions

Definitions follow the hcv-data reference for dashboard 6406. Where the HCV knowledge base disagrees, the choice made here is stated.

Scope
Porter HCV (9ft and above), intracity orders, Tier 1 cities (dim_geo_regions.tier = 'Tier 1'). Source: PROD_ELDORIA.MART.HCV_OVERALL_DEMAND_MART, one row per order, with the standard filters fo_deleted_at IS NULL and customer_mobile <> '0000000001'. An order is dated on date(order_time).
Intracity
lower(dim_vehicles.serviceability_segment) = 'vanilla', which leaves out Outstation vehicles. This is the vehicle-level definition and the same field dashboard 6406 offers as its Serviceability Segment filter. “Outstation” has other governed definitions (KB gap G-104); this report does not use a route-distance rule.
Demand
count(distinct unique_id). Every order placed, whatever its outcome.
Allocated %
Orders with fo_driver_id IS NOT NULL ÷ Demand.
Fulfilment %
Completed orders (fo_driver_id IS NOT NULL AND order_status = 4) ÷ Demand. This is the hcv-data / dashboard 6406 definition (card 55586). The HCV knowledge base disputes this denominator (gaps G-030, G-031): schedule-only rows that never became a trip can never reach the numerator, so they pull the percentage down. This report keeps Demand as the denominator so it ties to dashboard 6406.
CADF %
Cancelled after a driver was found (fo_driver_id IS NOT NULL AND order_status = 5) ÷ Demand. Split into customer / partner / porter by dim_cancel_reasons_attribution.attribution, joined on fo_cancel_reason_id; each split is also a % of Demand.
CBDF %
Cancelled before a driver was found (fo_driver_id IS NULL AND (order_status = 5 OR order_status IS NULL)) ÷ Demand. Stockout: no matchmaking batch was ever created (num_batches_created = 0). Missed order: a batch was created and no driver accepted (> 0). num_batches_created is the greater of the two production matchmaking marts (HCV_FO_MATCHMAKING_MART, HCV_SO_MATCHMAKING_MART). Dashboard card 55612 also reads a dev sandbox table here; this report does not, so its Stockout / Missed split can differ slightly from that card. A schedule booking cancelled before matchmaking starts has no batch, so it counts as Stockout.
Revenue
sum(FO_CUSTOMER_FARE_WITHOUT_PREVIOUS_DUE) on completed orders.
AOV
Revenue ÷ completed orders.
DAP
Daily active partners: a driver counts on a day when sum(business_login_hours) > 0.5 in core.fact_active_partners, for HCV vehicles in Tier 1 with the same intracity vehicle filter. A window shows the mean of the daily counts over the days that have loaded. DAP is not split by order type, because a partner is not an order type.
Allocation time
Seconds from order_time to driver acceptance (fo_trip_accepted_time), over orders that have an acceptance time and a non-negative duration, as dashboard card 55527 computes it. P50 and P90 are computed in SQL for each window; a percentile cannot be re-aggregated from daily values. A cell with fewer than 30 accepted orders is left blank.
Comparisons
Yesterday is set against the average of the last four same weekdays (counts are the mean per day, percentages pool the four days, allocation time is the mean of the four daily percentiles). Week to date starts on Monday and is set against last week cut to the same number of days. Month to date is set against last month cut to the same day of the month. Percentages change in percentage points (pp), times in seconds, everything else in % of the comparison value. Green means better for the business and red worse; AOV is not coloured.
Totals and cuts
Each order sits in exactly one city, one vehicle mapping and one order type, so every cut is a partition of the same orders and the Tier 1 total is computed from the orders themselves. No total is built by adding vehicle categories together.
Data maturity
Orders are read as they stood when the data was pulled. The newest day can still hold trips in progress, so its Fulfilment % may rise slightly on a later pull; a note at the top of the page gives the count.
Card and gap references
Card numbers are dashboard 6406 cards, whose stored SQL was read from PROD_ELDORIA.CORE.FACT_MB_CARDS on 27 Nov 2026. G-numbers are entries in the HCV knowledge base file hcv-selfserve/kb/GAPS.md. The week-level tie-out to cards 55586 and 55587 is in the reconciliation note beside this report.
Blank cells
A blank cell means there is nothing to measure (no demand, no completed order, DAP not loaded, or too few orders for a percentile). It never means zero.
